# Evidência — H01.3 Convidar e aceitar o segundo membro

Data: 24/09/2026. Estado: **concluída**.

## Escopo implementado

- Interface Angular/Material para o administrador criar, consultar, reenviar e revogar o convite e para o destinatário validar e aceitar o link. A mensagem informa que todo o histórico do espaço será compartilhado.
- API com CSRF, sessão JDBC e autorização administrativa. O convidado recebe `GUEST` e não consegue gerenciar membros; requisições sem sessão ou com papel incorreto são recusadas.
- Convite vinculado ao espaço/email, validade de sete dias, token aleatório persistido somente como SHA-256, uso único e invalidação por reenvio/revogação. O token não é ecoado nem registrado.
- Conta nova criada com senha BCrypt e email confirmado pela posse do link. Conta existente não confirmada é confirmada pelo convite; conta existente confirmada precisa autenticar exatamente como destinatária. Associação ativa anterior é recusada.
- Limite de dois membros protegido por lock pessimista do espaço e constraints duráveis. Aceites concorrentes do mesmo link produzem exatamente uma associação.
- Migração V4 cria `space_invitations`, FKs, hash único e índice parcial que permite somente um convite ativo por espaço.
- Email SMTP executado depois do commit, fora da transação longa. Se a entrega falha, o convite continua pendente e a interface passa a oferecer reenvio explícito. Mailpit permanece identificado como captura local.

## Critérios, decisões e limites

T06 registra o comportamento que os documentos não detalhavam: um convite pendente não é trocado silenciosamente; conta confirmada preexistente entra como o mesmo email; conta preexistente ainda não confirmada é confirmada pela posse do convite. A UI e a API recusam terceiro membro, identidade divergente, convite expirado, consumido, revogado ou substituído.

Mailpit comprovou a integração SMTP local e o conteúdo do link; a composição descartável comprovou separadamente a entrega Gmail real. A CA pública do Avast já confiada pelo Windows foi exportada somente para a imagem descartável, sem desabilitar STARTTLS ou validação. Contêineres, volumes, CA exportada e arquivo local da senha de app foram removidos ao final. A credencial não foi versionada, lida em saída ou registrada em logs/documentação.
